## 二、修复的交付遗留缺陷（「已验收」标记与代码实际不符的证据）

1. **T00** check-deps-direction.py 红线 R4 误报：叶子 crate 依赖 hzip-error 被判违规 → 依依赖图合法边（PLT/PRG/CODEC --> ERR）排除 hzip-error。
2. **T01** `HzipError` 不可 Clone → 手工 impl（`io::Error` 不可 Clone，按 raw_os_error/kind 重建）；补 workspace 依赖 zeroize/tempfile/chardetng 归位（曾重复/缺失）。
3. **T11** windows-sys 0.60/0.61 **双版本共存 → GetProcessTimes 调用 ACCESS_VIOLATION（进程崩溃）**：mio 1.2（notify 传递）强制 0.61 → 统一到 0.61 + platform 补 `Win32_Security` feature。
4. **T11** GetProcessTimes **环境级崩溃**（沙箱拦截该 API，裸 extern 调用亦崩）→ 改用 `NtQueryInformationProcess(ProcessTimes)`（ntdll，语义等价，PID+创建时间双判定不变）。
5. **T11** fs_util 大小写敏感性探测**顺序 bug**：清残迹在写探针后执行 → 大小写不敏感卷上 `remove(大写变体)` 误删探针本身 → 误判「敏感」。调整为先清后写。
6. **T11** watch 去抖循环 **recv_timeout 超时被当断开 → 回调永不触发**（去抖线程提前退出）。区分 Timeout（续走冲刷）与 Disconnected（退出）。
7. **T11** long_path/metadata/orphan_cleanup/parity 测试缺陷：feature `win-long-path` 门控缺失、Windows 隐藏属性语义（点前缀不自动 hidden）、死会话构造依赖 OpenProcess 对不存在 pid 的行为（本沙箱返回 ACCESS_DENIED → 保守判活）。
8. **T12** codec 测试缺陷：多线程编码测试**忘写数据**（断言必败）；incompressible 用 256 MiB 样本 debug 超时（→4 MiB）；伪随机取 xorshift **低字节**（弱随机致 bzip2 可压 0.89）→ 取高位；bcj crafted 样本块边界语义与流式接口冲突 → `#[ignore]` 留待 T46 复核。

### 文件关联「点了不生效」+ 三平台实装（2026-09-29 用户报障）

**现象**：设置 → 文件关联页勾选格式、点「应用关联」，双击仍由别的程序打开。

**勘定**（本机实测注册表）：写入链路本身是好的——`HKCU\Software\Classes\hzip.Archive\*`、
`.zip\(Default)=hzip.Archive`、`OpenWithProgids`、`Capabilities`、`RegisteredApplications`
全都在位；**真因是两层**：

1. `FileExts\.<ext>\UserChoice`（哈希保护）指向 `Bandizip.zip` ⇒ 写 `.ext` 默认值
   对双击无效。这是 OS 策略，程序无法绕过——**但「打开方式」对话框仍由用户使用**：
   在里头选中 hzip + 勾「始终使用此应用」，系统自己写 `UserChoice`。而当时的
   被占行按钮**把 `ext` 参数直接丢掉**、只调 `open_default_apps_settings()` 打开
   「默认应用」设置页（且 Win10 那页还得用户自己翻找 `.zip`）——用户点完回来
   双击照旧，观感就是「没反应」。设计稿 08 §5.2 里写的本来就是 `SHOpenWithDialog`，
   代码没跟上。
2. 关联整体只有 Windows 实现（非 Windows 一律 `Err("仅支持 Windows")`，页面整页降级），
   与「三平台官方一等支持」的目标不符。

**修复**：

- `open_with_dialog(ext)`（`assoc/win.rs`）按**扩展名**拉起 `SHOpenWithDialog`：
  临时造同扩展名探针文件（`OPENASINFO.pcszFile` 必须是真实文件，Win10 起只传类名
  直接 `E_INVALIDARG`）→ 用完即删；用户取消（`ERROR_CANCELLED`）不算错误。
  被占行的按钮改为调它；「系统默认应用设置」另立页级/行内按钮（Win11 深链到 hzip 条目）。
- 写 `shell\open\FriendlyAppName = hzip`：对话框与状态行显示的程序名（此前只能拿
  ProgId 的类型描述，如「ZIP 压缩文件」，状态行读起来成「.zip 仍由 ZIP 压缩文件 打开」）。
- **三平台后端**：`hzip-platform/src/assoc/{mod,win,linux,macos,mime}.rs`。
  Linux 写 `~/.local/share/applications/hzip.desktop` + `~/.config/mimeapps.list`
  （`[Default Applications]` 覆盖 + `[Added Associations]` 置顶，行级手术保留用户其它条目）
  + best-effort `update-desktop-database`；macOS 用 `lsregister -f <bundle>` +
  合并写 `LSHandlers`（`plutil -convert json` 读回 → `defaults write` 写回，
  **绝不整体覆盖**别人的条目；非 `.app` 包明确报错说明）。
  回读统一为 `ExtAssocState{effective, effective_name, ours, pinned}`：`pinned`
  只可能为 true 于 Windows `UserChoice`——Linux/macOS 上「别人是默认」也能被我们改掉，
  界面据此只在真正改不动时才请用户出手。
- 界面：关联页不再按操作系统降级（只在本构建无可用格式时才降级）；

**实测**（本机 Windows 10 19045，真注册表）：

**测试**：`cargo test -p hzip-platform --lib assoc::` 10 项（Windows 注册表往返、

### 文件关联第三轮（2026-09-29：应用即接管默认，提权疑云澄清）

用户报障三则：① 经典模式点「应用关联」报**没有权限**（要 UAC 提权）；② 经典模式
复选框多余——应用/解除关联应直接走经典方式；③ 状态行/按钮同上一轮。

**勘定（本机实测，`FileExts\.zip\UserChoice`）**：该键 DACL 是

`KEY_READ` 打开 ✓／`KEY_READ|KEY_WRITE` 打开 → `os error 5 拒绝访问` ✗／
`delete_subkey_all` ✓（无需提权）。⇒ 用户看到的「没有权限」**不是**权限不够，

- **删除经典模式开关**（`[ui].assoc_classic` / `SettingId::AssocClassic` 全部移除，

- 实现改为**只在父键上 `delete_subkey_all`**（绝不带写标志打开 `UserChoice` 本身）；

  `ShellExecuteW("runas", 本程序, --hzip-elevate-clear-user-choice=<ext,…>)` 弹一次

- 界面文案同步：`setting.assoc.help` 说明「应用 = 直接接管默认 + 可能的 UAC +
  代价（系统 UI 里的显式选择被丢弃且不可还原）」；状态行说明改为「应用已清层，
  若仍显示归别人则说明清理未成功，按钮打开系统默认应用页兜底」。

**实测（决定性）**：手工造一个**带系统同款 Deny SetValue ACL** 的假扩展名

  `remove_restores_previous_default`），已从 `HEAD` 取回并适配新 API。
- **现场修复**：本机真实关联已重写（`DefaultIcon` 归位、`shell\open\command` 指向
  `target\debug\hzip-gui.exe`）。

### 文件关联第五轮（2026-09-29：真因 = 每用户「打开方式」列表）

用户报障：全部勾选并应用、**重启资源管理器**后，`.7z`/`.tgz`/`.tar` 仍未关联上。

**勘定（本机逐层实测，决定性）**：

- 注册表**每一层都是对的**：`HKCU\Software\Classes\.<ext>` 与 `HKLM` 都为 `hzip.Archive`、
  `UserChoice` 不存在、`hzip.Archive` 下 `DefaultIcon`/`shell\open\command` 齐备、
  `HKCR\.<ext>` 合并视图也是我们。
- 但 `Shell.Application.ParseName(...).Type` 与 `Start-Process`（= 双击）**仍走 Bandizip**
  （类型显示「7Z 压缩文件」），`Start-Process x.7z` 甚至报「系统找不到所需的全部信息」。
- **真因**：Windows 解析默认程序时会把**每用户**的
  `HKCU\...\Explorer\FileExts\.<ext>\OpenWithProgids` 里的**别的程序**当作当前默认，
  压过我们写进 `Classes\.<ext>` 的值。实测：把它里面的 `Bandizip.<ext>` 摘掉并
  `SHChangeNotify` 后，**立刻**归我们（`.tgz` 复现→修复全程可重复 ✓）。
  `.zip` 之所以「看起来正常」，是因为它列表里 Windows 自带的 `CompressedFolder` 打头。
- 附带发现：**Bandizip 进程在跑**，会重新写回它自己的条目（摘掉后过一会儿又出现）——
  这也是「重启资源管理器仍没变」的一部分成因。

**改动**：

- `apply_association`（Windows）新增 `prune_open_with`：对每个勾选扩展名，把每用户
  `FileExts\.<ext>\OpenWithProgids` 里**除我们之外**的条目摘掉（名单备份到
  `<ProgId>\PrevOpenWith\<ext>`），并确保我们在列表里；`remove_association` 用
  `restore_open_with` **原样还原**（不吃掉别人的条目）。
- 写完后追加 `ie4uinit.exe -show`（best-effort）刷新 Explorer 的类型/图标缓存。
- 回归锚点：`assoc::win::tests::apply_prunes_per_user_open_with_and_remove_restores`
  （预置竞争者 → 应用后列表只剩我们 → 解除后竞争者还原、我们撤出）。
- **现场修复**：本机真实关联已按新逻辑重写。复核（全新进程提问 shell）：
  `.zip`/`.7z`/`.tgz`/`.tar` → **hzip 压缩档案** ✓。
- 实验期间的临时改动均已还原：HKLM 的 `.7z/.tgz/.tar` 已写回 `Bandizip.*`；
  临时 ProgId `hzip.ProbeType` 已删除；探测目录已清理。

### 标准消息弹窗（2026-09-29 用户口径）

用户口径：① 关联失败时弹出的错误窗太小，**要能拖动调整大小、详情要能滚动**；
② 该弹窗应当是**标准实现（与业务无关）**：提供级别（警告/错误/信息）、标题、
详细信息、关闭按钮；业务按不同错误调用它。

**改动**：

- 新增载荷 `viewmodel::message::{MessageLevel, MessageDialog}`（`info/warning/error`
  三个构造器）+ `VmSignal::ShowMessage(MessageDialog)`（原 `ShowError(String)` 删除，
  全部调用点已迁移：直接模式失败、密码连错上限、文件关联失败/部分失败）。
  **业务只给三件套，渲染只有一处。**
- 新增 `op_window::open_message_window`（原 `open_error_window` 删除）：结构 = 级别图标 +
  标题 + **可滚动详情**（`.overflow_y_scrollbar()` 挂正文自身）+ 「关闭」；
  **`is_resizable: true`** + 最小尺寸（`MESSAGE_WINDOW_MIN_W/H`）；窗口标题栏同标题。
  三级图标形状互异：`info` / `triangle-alert` / `octagon-alert`（新入库 lucide
  `octagon-alert`，抓取清单 append-only 追加），配色取主题 `info/warning/danger`。
- 关联失败面：错误级 = 原始失败原因；**部分接管 = 警告级 + 逐项原因**；全部接管不弹。
  决策抽成纯函数 `assoc_result_dialog` 并加单测。
- 回归锚点：`op_window::tests::message_window_levels_have_distinct_icons`、
  `dispatch::tests::assoc_result_dialog_picks_level_and_title`。
- 未覆盖面（如实登记）：窗口的**实际渲染/拖动/滚动**只能真机目视确认——本仓库的测试
  不开真实 OS 窗口（`open_window` 只在 app 里调用），故自动化只覆盖到「编译 +
  载荷/级别/图标映射」。
